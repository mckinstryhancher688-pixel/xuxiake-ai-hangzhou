# 设计稿 · A 方案：单人 + 事实层免费重解（亲情场景）

> 状态：**设计已对齐，待实施。** 分支 `feat/family-mode`，备份点 `pre-family-2026-11-15`（=`3d02020`）。
> 决策依据：用户确认「按事实层免费重解做」；砍掉双人多角色协议，主链路回到单人核验。

---

## 1. 一句话

**核验花钱一次；之后改「爸妈能走多远」永远免费。**

```
POST /api/verify   （真实付费一次，产出事实层）
        ↓ factsId
POST /api/resolve  （新端点，0 新增高德，可无限次改条件）
        ↓
行程 + 因果说明（哪条约束删掉了哪个站）
```

## 2. 为什么不用把上限塞进 /api/verify

`/api/verify` 的缓存键是 `城市|类别`，且流水线是「先测完全部路段、再穷举组合」。
把 `maxWalkMeters` 放进去会逼出两个后果：

1. 缓存键得加上限 → 每换一个上限就是一次**全冷跑（约 61 次高德）**；
2. 「妈刚说走不动，改一下」会变成付费动作。

而事实层已经存好了**全部已测有向路段**，改条件只是换一个求解目标。所以正确的位置是 `solveJoint(facts, a, b=null, now)` —— 已验证**原生支持单方**（`b ? [a,b] : [a]`），且硬条件里已有 `maxWalkMeters`（solve.ts:241）。**求解器一行不改。**

## 3. 新端点 `POST /api/resolve`

### 请求
```jsonc
{
  "factsId": "…",                 // 来自 /api/verify 的 report.facts.factsId
  "maxWalkMeters": 1500,          // 可空；200~40000 整数
  "mustVisit": ["1892"],          // 可空
  "neverAccept": [],              // 可空
  "attemptId": "…"                // 幂等键
}
```

### 响应
```jsonc
{
  "ok": true,
  "itinerary": { /* VerifiedItinerary，与既有结构一致 */ },
  "constraints": { "maxWalkMeters": 1500, "mustVisit": ["1892"], "neverAccept": [] },
  "evidence": {
    "totalWalkMeters": 1200,
    "withinLimit": true,                 // 服务端判定，前端只展示
    "limit": 1500,
    "whyDropped": [                      // ★ 因果回显
      { "name": "满陇桂雨", "reason": "保留它会走到 2100 米，超出你定的 1500 米" }
    ],
    "keptBecauseMust": ["平湖秋月"]
  },
  "cost": { "newAmapCalls": 0, "cacheHits": "fact-layer" },
  "note": "…COST_SCOPE_NOTICE 原文…"
}
```

### 事实层的真实边界（重要，必须如实告知）
`facts.pool` 是**全部可路由候选**（实测 poolSize 可达 8），但 `facts.legs` 只实测了：
「起点 → 最近 6 个站」＋「这 6 个站两两之间」。

| 操作 | 新增调用 |
|---|---|
| 改 `maxWalkMeters`（任何方向） | **0** — 只在 6 个内重排/减站 |
| 改 `neverAccept`（目标在 6 个内） | **0** |
| `mustVisit` 指向第 7、8 个站 | **需补测** → 返回 `missingEdges` 与报价，不自动执行 |
| `mustVisit` 与 `neverAccept` 冲突 | 0 — 直接返回 `hard-conflict` 与证据 |

界面必须照实写：可以随时免费调整的是「走多远、去不去这 6 个里的某几个」；
要加进第 6 个之外的站，会明确提示"需要补测 N 段，要不要花钱"。

### 关键规则（不可放松）
- **上限判定只由服务端做**。前端只读 `withinLimit`，不得自行比较。
- 无解时**不静默降级**：返回 `ok:false` + `reason`（如「按 1500 米最多只能排 2 站，少于最少 3 站」），并给出「放宽到多少米才能排 3 站」的建议值——这个建议值必须来自枚举，不是拍脑袋。
- `factsId` 过期（>6h 或服务重启）→ 410 + 明确文案「重新核验会真实消耗约 36~62 次高德请求，所以这里不自动重跑」。
- **0 新增调用**必须由 `amapCounters()` 前后比对证实并写进响应，不接受"应该不会花"。

## 4. 单人可直接执行（必须补的门禁分支）

现状：`confirmRevision` 里 B 未表态时只给 `confirmed-one`，`officialRevision` 恒为 null，`canExecute` 恒 false。单人流要跑通，需要**独立于双人状态机**的一条判定：

```
单人可执行 = 行程非空
           ∧ 所有站 matchStatus !== "unverified"
           ∧ 所有站 openingStatus !== "conflict"
           ∧ 满足约束（totalWalkMeters ≤ maxWalkMeters，mustVisit 全在，neverAccept 全不在）
```

**不复用 `canExecute`（那是双人专用），新写 `canExecuteSolo()` 纯函数 + 单测。** 这样双人逻辑不受影响，将来要恢复也不用回滚。

## 5. 因果回显怎么算（纯函数，可单测）

对每条约束，做一次「反事实对比」：

| 约束 | 反事实 | 产出文案 |
|---|---|---|
| `maxWalkMeters` | 用 `Infinity` 再解一次 | 「不设上限会排 4 站、走 2100 米；按你说的 1500 米，删掉了满陇桂雨」 |
| `mustVisit` | 去掉该 id 再解一次 | 「因为你说必须去平湖秋月，保留了它，代价是多走 300 米」 |
| `neverAccept` | 加上该 id 再解一次 | 「因为你说不去满陇桂雨，这条路线里没有它」 |

**成本**：反事实解都是纯本地枚举（`solveJoint` 不含任何 IO），**0 调用**。枚举规模 ≤ `permutations(pool≤6, ≤4)` = 有限，实测在毫秒级。

**诚实规则**：只说"因为这条约束，删掉了 X"，**不**声称"删掉 X 就不累了"。因果只到"数字层面"，不到"身体感受"。

## 6. 界面（最小版）

核验完成后，行程上方加一行：

```
爸妈能走多远？  〔半小时 · 1.5 公里〕〔一小时 · 3 公里〕〔不设限〕   ← 选了就重解，免费
```

选中后：
- 行程卡片立即更新；
- 顶部一条：**「全天 1.2 公里，在你定的 1.5 公里以内 ✅」**（人话回显，就是 `withinLimit` 翻译过来）；
- 下方「为什么是这几个」：因果回显列表。

**不做**：不做"双方确认"仪式、不做角色链接、不做差异正负号表（那是陌生搭子才需要的东西）。

## 7. 不动 / 停用清单

| 项 | 处理 |
|---|---|
| `/api/verify` 流水线、事实层、`solveJoint`、`composeItinerary` | **不动** |
| 来源证据条（B1/C）、数据可信说明 | **不动**（已验收） |
| `/api/plan` 全套、`PlanClient`、角色链接 | **停用**：不再从主界面进入，文档不再宣传。代码保留（备份分支还在） |
| 双人状态机 `plan-state.ts` | **不动**，只是不再被主链路调用 |

## 8. 验收标准（做完要能跑出这些）

1. 真实核验一次 → 拿到 `factsId`；
2. 连续用 3 个不同 `maxWalkMeters` 调 `/api/resolve` → **`amapCounters()` 三次均不变**（写进证据 JSON）；
3. 每个结果都满足 `totalWalkMeters ≤ limit`（服务端断言）；
4. 无解时给建议值，且建议值经枚举验证确实可行；
5. 因果回显经反事实计算，数字与两次求解结果一致；
6. 手机端一行「爸妈能走多远」不溢出。

## 9. 成本

| 阶段 | 调用 |
|---|---|
| 核验（一次） | 约 36（单类别）~ 62（双类别）次高德 |
| 改上限（任意次） | **0** |
| 因果回显 | **0** |

若后续要加「沿途无障碍洗手间」：每次核验 +1 次 `place/text types=200303`（已实测可用），需要单独报预算。
