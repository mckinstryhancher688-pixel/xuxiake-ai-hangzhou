# 演示与验收手册 · 旅行搭子协商

主线：**一方不接受原路线 → 提出个人条件 → 比较真实取舍 → 双方确认同一版。**

适用范围为两位成年搭子、杭州半日出游。本文只组织演示与复现，不改变部署方式、密钥配置或求解逻辑。
能力是否已经真实验证，以 [EVIDENCE.md](EVIDENCE.md) 为准；投稿正文见 [SUBMISSION.md](SUBMISSION.md)，
上线架构与安全事项仍分别由 [DEPLOYMENT.md](DEPLOYMENT.md)、[SECURITY.md](SECURITY.md) 说明。

## 1. 先选一条有证据的故事

历史运行截图中，同伴将步行上限填为 **5001 米**（显示约 5 公里）后，路线发生如下变化：

| 项目 | 原方案 | 新方案 |
| --- | --- | --- |
| 高德规划步行距离 | 7.50 公里 | 3.77 公里 |
| 高德预计步行耗时 | 100 分钟 | 50 分钟 |
| 含设定停留和缓冲的总时长 | 210 分钟 | 130 分钟 |
| 景点取舍 | 含满陇桂雨 | 保留平湖秋月、三潭印月；删去满陇桂雨 |

证据：[条件与差异](../evidence/phase9-04-B-diff.png)、[双方确认后地图](../evidence/phase9-07-A-joint-executing.png)。
它们是历史记录，含当时的旧英文状态标签；后续已改文案，但没有重拍对应真实画面。

现场重新生成时，按**当次实际路线**选择案例，不要求出现同一组站点、距离或版本号。
不要预设「3000 米一定冲突」「改成 6000 米一定可行」。只有实测数据支持时才展示冲突结论；
缺路段只能说尚未核验，不能说走不到。若本轮没有合适冲突，可以直接展示历史证据并注明时间。

## 3. 演示前准备

- 本地启动说明见 [README](../README.md#快速开始)。项目要求 Node ≥20.9.0；留存离线验收使用 Node 24.20.0。
- 核对自己的 8 项服务配置，但不要展示值。只读状态端点能看额度与配置形状，**不能证明所有凭据可用**。
- 完成构建、启动最终服务实例之后再预热。不要在录制期间重启服务或改类别，否则可能失去原缓存。
- 当前默认单选「文创街区」，假定杭州时间 13:00 出发。自然风光可能返回远郊候选，无解就如实展示，不连续冷重试。
- B 页已有正式行程卡，可在同标签页进入主界面；不会重新冷核验。正式地图缺折线时不补测、不画直线。
- 双人快照需要可写目录；位置由 `PLAN_SNAPSHOT_FILE` 或默认 `.data/plan-snapshot.json` 决定。不要为录屏删除已有真实快照。
- 公网入口为 [travel.peiqirui.com](http://travel.peiqirui.com/)，2026-10-24 已发布 `c906649`。手机不能通过自己的 `localhost` 访问电脑服务；两端需使用同一服务地址。真实业务闭环仍待另行验收。
- 角色链接就是凭据：**全程隐藏或打码 A/B 链接、地址栏中的 token、二维码与剪贴板提示**。不采用“短暂露出就没关系”的做法。
- 只录产品页面，折叠 DebugPanel，不录配置文件、原始响应、终端密钥或本机个人路径。

### 调用成本口径

| 动作 | 历史观察 / 当前规则 |
| --- | --- |
| 首次冷核验 | 单类别历史约 36 次高德请求（11 POI + 25 步行）；双类别约 62 次（21 + 41）。实际数随候选、缓存和失败重试变化 |
| 飞猪发现 | 每个类别一次 CLI 查询；结果缓存 10 分钟，12 次/小时上限 |
| 百炼讲解、单人减法、双人解释 | 每个成功进入真实调用的动作分别消耗回合；上限 40 回合/小时 |
| 创建双人方案、确认 | 复用现有事实，不因这两个动作重新冷核验 |
| 修改条件或提案 | 所需实测有向段齐备且仍有效时，本地重解不新增高德调用；缺边可能补测 |
| 补测 | 超过 6 条缺边时等待成本批准；1～6 条仍可能直接补测。受单轮 9 条、单方案 18 条和小时余量约束 |

“同一缓存”需要类别、实例、有效期等条件匹配，不能承诺连续跑所有脚本只花一次冷核验。
已过期的事实不能通过重启或换说法续期；真实端点的额度拒绝与错误应如实保留。

## 4. 手工操作与观感清单

电脑端：

- [ ] 首屏有明确的生成入口，地图和卡片可见，无阻塞弹窗。
- [ ] POI、路径数据与模拟停留的来源能辨认。
- [ ] 地图点选与卡片对应，缩放后能查看全程。
- [ ] A 发起协商；B 进入独立角色页面，仅持 B 的凭据不能替 A 确认。
- [ ] B 改硬条件后，旧确认先挂起；不能继续用已不满足条件的旧方案。
- [ ] 差异保留正负方向；没有把增加的距离说成“节省”。
- [ ] B 单独确认时仍未共同生效；A 也确认同版后，地图与执行面板采用该版。
- [ ] 普通改线提案不会在对方确认前替换当前正式版；硬条件变化则需要重新协商。
- [ ] 双方确认版的单人“少走一点”受限；后续调整从协商入口提出。
- [ ] 百炼失败显示真实错误，规则结果保留；不以固定话术冒充模型。

手机视口 / 真机分开记录：

- [ ] 390×844 视口首屏能操作，底部按钮不压住正文。
- [ ] B 链接可进入正确角色，状态能与 A 同步。
- [ ] 拖拽、滚动和地图切换不误触按钮。
- [ ] 若只用浏览器手机视口，记录为“手机视口”，不写“两台真机”。

出现界面旧英文标签时，应重拍实际当前界面后再替换历史图；不能直接改图消除缺陷。

浏览器脚本需要既有可用的 Playwright 与 Chromium 环境，并非项目依赖安装后自动具备。
历史本机文案探针全程 0 次 POST，未随仓库发布；不要与真实生成路线的脚本混称。

保存新日志的示例（不要覆盖历史文件；日期时间取实际运行时刻）：

PowerShell：

```powershell
$stamp = Get-Date -Format 'yyyyMMdd-HHmmss'
node evidence/phase9-accept.mjs 2>&1 | Tee-Object -FilePath "evidence/phase9-accept-$stamp.log"
```

Bash：

```bash
set -o pipefail
node evidence/phase9-accept.mjs 2>&1 | tee "evidence/phase9-accept-$(date +%Y%m%d-%H%M%S).log"
```

这些是真实脚本的运行示例，本轮文档整理没有执行它们。非默认服务地址使用 `BASE_URL`；PowerShell 用
`$env:BASE_URL = 'http://localhost:端口'`，Bash 用 `export BASE_URL=http://localhost:端口`。
