# 旅行空间与攻略检索模式

本轮实现、真实验收结果与未完成事项见[2026-11-01验收记录](WORKSPACE-ACCEPTANCE-2026-11-01.md)，待发布步骤见[上线说明](WORKSPACE-RELEASE.md)。新入口默认关闭，尚未部署到生产。

一个人先收集攻略，需要时邀请一位搭子；双方独立表达底线，以真实路段比较取舍并确认同一版本。

## 开启与数据保存

应用运行时使用 Node 24.20.0。设置服务端 TRIPS_ENABLED=1 后，首页出现新入口，地址为 /trips。不开启时旧页面和旧 API 保持原行为。生产资料上传仅应通过 HTTPS 开放。

不需要 Python 或独立向量数据库。TRIP_DATA_DIR 默认为 .data/trips；若配置了 PLAN_SNAPSHOT_FILE，则默认放到该快照目录下的 trips 子目录。数据库 trips.sqlite、WAL 文件和 images 子目录必须共同位于持久化卷，不能放在每次发布会被替换的构建目录中。

新空间及其资料、成员、确认记录保留创建后的30天；旧双人快照保留原兼容路径。路线事实仍按原始采集时间判断六小时有效期，重启不续期。数据库仓储通过事务与版本比较保证保存，不依赖进程内缓存。

部署前停止写入并备份整个目录，或使用 SQLite 在线备份接口并单独备份图片。不能只复制一个仍在写入的主数据库而忽略WAL。回滚应用时关闭新入口并保留数据，不删除数据库或旧快照。

TRIPS_WORKER_PAUSED=1 可暂停后台队列；原资料仍能保存。正常运行不要设置此项。单实例、单Node进程是当前部署边界。

## 使用流程

1. 发起人创建空间，保存自己的私有恢复链接。
2. 上传文字或清晰截图；也可先发邀请。预览链接不算加入，接受邀请才占用B身份。
3. 两人均可贡献资料，但只能修改自己的原资料和个人条件。未填写不代表同意。
4. 地点卡上的勾选表示进入本轮比较；偏好与必须去／绝不接受分别填写。攻略频次不会自动变成必须去。
5. 需要更多候选时主动点击飞猪补充。飞猪只使用现有城市／类别搜索，不承诺任意自然语言搜索。
6. 查看核验报价，再决定是否核验。地点不明确时先从高德返回结果中确认；相同高德身份可在生成路线前合并。
7. 有完整事实时重算与删站使用已有路段，缺失数据才补测。双方分别确认同一版本后，才显示双方已确认。

B加入前，A可确认个人路线。B加入后原个人执行权限立即挂起；B提交条件或明确无附加条件后重算，并由两人重新确认。发出邀请本身不暂停个人使用。

恢复链接是角色访问凭据，不能当邀请链接公开转发。邀请有效期最长七天，重新生成会使旧待接受邀请失效。本期最多两人，不支持替换已加入成员。

## 输入、检索与来源

每空间最多20份资料，其中截图最多五张；单张5MB以内，JPEG/PNG/WebP；单份文字最多一万字。PDF、网页全文自动抓取、扫描长文和实时共同编辑暂不支持。

文字／截图由独立的 qwen3-vl-plus 调用抽取文字与地点，随后按段落切分，并由 text-embedding-v4 生成512维向量。两项均复用服务端已有百炼密钥，不修改原Managed Agent配置。模型不可用明确提示，保留原资料，不换提供方或伪造结果。

检索在已授权空间内执行：中文分词、别名/同义概念与BM25召回，加上向量余弦召回，两路各最多20条，RRF合并后最多六条进入资料问答。向量不可用时保留关键词检索并提示降级。资料问答使用关闭工具的独立Managed Agent会话，不调用飞猪或高德。

引用定位到资料、上传人、段落与原图。相同内容或相同声明来源合并计数；无出处且内容不同的搬运稿不能保证被识别为同源。提及次数来自完整结构化记录，不由TopK检索估计。正面推荐与不推荐分开保留；图片识别可人工纠错。

资料观点、个人决定、外部返回和路线结论分别保存。外部查询与AI总结不增加攻略提及次数；攻略中的步行耗时不进入实测数字白名单。新增或删除资料不会自行改写已确认路线。

## 调用与失败处理

新通道每空间每日最多20次资料处理、30次问答；全局每小时最多40次新增AI请求。飞猪、高德和Managed Agent原有上限继续生效。额度及请求结果保存在SQLite；同一请求标识复用任务，HTTP重试计入外部请求记录。

首轮最多比较六个候选，若要全测，对应最多36条有向步行段；必须去和强偏好优先，超过范围需主动缩减。后续缺边受单轮九段、累计十八段与发起人批准阈值约束。保留每条成功购买的数据，不能用重建计划或重启绕开额度。

任务结果未知时不自动重买。修正资料或查看已有数据后再手动重试。地点／条件在测量过程中改变时保留获得的数据，但不把旧输入生成的路线提交为新方案。

## 接口

新资源统一位于 /api/trips：创建、空间读取、invitation、invitation/preview、join、materials、conditions、candidates、merge、ask、explain、enrich、quote、verify、resolve、shorten、confirm、jobs。

路线卡上的“请 AI 解释这一版的取舍”调用独立的关闭工具的百炼会话，同时读取本版服务端事实与有限攻略观点。距离／时间只使用原事实白名单；遇到无法核实的数字或确认说法，明确退回服务端事实摘要。解释绑定路线版本、内容哈希和资料版本，不能让旧解释覆盖新条件。

角色由 x-trip-token 请求头识别，不信任正文role。邀请使用 x-trip-invite，认领使用客户端稳定的 x-trip-claim 防止响应丢失后重复占用。写操作包含 expectedVersion，付费任务另包含 requestKey。图片上传使用独立multipart分支和流式大小限制；不经过旧8KB JSON入口。

旧 /api/plan 系列接口和旧快照不迁移内容哈希。新路线使用独立stopId；没有飞猪匹配时flyaiId为null，原始飞猪ID不会被伪造。

## 验证与交付

- npm run test:trips：临时SQLite、夹具与禁止网络的验收，涵盖权限、邀请、版本、来源、路线衔接和恢复。
- npm run test:offline：原有离线验收。
- npx tsc --noEmit、npm run lint、npm run build：类型、静态检查和生产构建。
- npm run test:rag:live：**会产生真实百炼向量调用**，使用10段人工编写的测试资料与20个标注问题，要求前六片段命中至少18题；不代表真实旅行事实或总体用户准确率。

真实验收材料与模型评测结果必须区分：测试文本/截图是人工夹具，路线距离/时间和折线来自高德，停留30分钟与余量20分钟仍是产品设定。本轮没有组织真实用户招募或声称完成三至五组外部搭子试用。

上线前需要在实际域名验证HTTPS、地图JS域名配置、持久化卷和一次双浏览器流程。已有服务密钥与Agent配置保持不变。

新入口复用旧引擎的行政区、坐标系和地点类型比对；八公里直线范围仍是地点政策限制，不是用直线代替实际步行。名称相同的未定位标签可先归组，已定位地点不会因新来源同名而自动合并；高德身份一致后，生成路线前允许明确合并。生成路线后保留历史标识，可主动只选一个别名参与新比较，不自动改写历史。

飞猪分类补充额外使用SQLite十分钟缓存，保存原采集时间，跨重启复用；不把外部资料算作攻略提及。个人条件变化后若无解，界面保存并展示求解冲突或缺边证据，原路线仅供比较。

“本轮待规划”是手动选择与双方已提交“特别想去／必须去”的地点并集，按地点去重，最多六个。界面与服务端共用计数规则，展示自动加入的名称和原因；最终从这些候选里比较去哪些、按什么顺序走，最多安排四站。个人保留的地点显示选中并说明原因，不能只取消普通勾选就绕过本人或搭子的已提交选择。超限时先调整候选或由本人修改并提交条件，查看报价前就能看到原因；不会自动扩大查询额度。
