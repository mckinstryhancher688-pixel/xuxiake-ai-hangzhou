## 1. 凭据边界

| 变量 | 谁能看到 | 落点 |
| --- | --- | --- |
| `AMAP_JS_KEY` | **浏览器**（JS API 类型 key 设计上必须交给浏览器加载 SDK） | 只出现在高德 SDK 的 script 地址里 |
| `AMAP_JS_SECURITY_CODE` | 只有服务端 | 在 `/amap-proxy`（浏览器侧经 rewrite 走官方一级路由 `/_AMapService`）里才拼进上游请求（`src/lib/server/amap-js.ts:145`） |

- 服务端读到的环境变量**全部没有 `NEXT_PUBLIC_` 前缀**（8 个必填 + 3 个可选）→ 不会被打进浏览器 bundle。
- `.env.local` 被 `.gitignore` 的 `.env*` 规则忽略，仓库里只有 `.env.example`（只有变量名，值为空）。
- 验收套件会把 `.env.local` 里的真实值拿来在页面 HTML 与文本节点里做包含检查（`evidence/phase6-accept.mjs` 末尾两项）。跑线上时本地没有 `.env.local`，这两项自动跳过并在日志里说明原因——因为线上凭据在平台环境变量里，本来就没有可比对的明文。
- 刷新恢复用的是 **sessionStorage**（`src/lib/session-snapshot.ts`），不是 localStorage：随标签页关闭即消失，不跨设备、不进服务端。里面只有会话票据（浏览器侧随机串）、已核验行程与讲解文本；真实的百炼 Session ID 与所有密钥都不在其中，票据本身在服务端映射不到任何凭据。

## 4. 高德安全代理不是开放代理

实现见 `src/lib/server/amap-js.ts`，逐条今天实测：

| 约束 | 实测 |
| --- | --- |
| 上游主机固定（`restapi.amap.com`；只有 `v4/map` 样式走 `webapi.amap.com`），调用方无法指定主机 | 转发目标由代码拼，URL 里没有可注入的主位 |
| 只放行 `v3/v4/v5` 前缀 | `GET /amap-proxy/v2/whatever` → **400** `高德代理只转发 v3/v4/v5 开头的请求。` |
| 路径片段字符白名单 + 显式拒绝 `.`/`..` 点段 | `curl --path-as-is /amap-proxy/v5/../../etc/passwd` → **404**（Next 路由层就没匹配上，处理器的点段拒绝是第二层） |
| 带 `key` 的请求必须等于本站 JS key | `?key=deadbeef…` → **403** `高德代理拒绝了不属于本站 JS API Key 的请求。` |
| 只接受 GET / POST | 其他方法 → 405 |
| POST 体积 ≤ 256 KB（本次新增） | 300 KB 请求体 → **413** `高德代理只转发不超过 256 KB 的请求体。`（检查放在配额计数之前） |
| 每分钟 240 次、上游超时 12s、错误文本 scrub 掉密钥 | `PROXY_MINUTE_CAP` / `PROXY_TIMEOUT_MS` / `scrub()` |

**两个入口，一套守卫。** 高德 JS SDK 硬性要求安全代理的一级路由是 `_AMapService`，写成别的路径就会在首次加载时弹阻塞提示。App Router 把下划线开头的目录当私有目录、不参与路由，所以 `next.config.ts` 用 rewrite 把 `/_AMapService/:path*` 映射到真实 handler `/amap-proxy/:path*`：

- 浏览器与 SDK 只看到 `/_AMapService/…`（`/api/map-config` 下发的 `securityHost` 就是它）；`/amap-proxy` 这个内部路径不会出现在浏览器里，验收脚本按请求 URL 计数断言这一点。
- 两个入口进的是同一个 `proxyAmapRequest()`，上表每一条对两个入口都成立；直接打 `/amap-proxy/v9/probe` 与 `/_AMapService/v9/probe` 都返回同一条 400。

**残余风险（不粉饰）**：JS API Key 天生是公开的——它就印在页面里。拿到它的人可以通过本站代理以 ≤240 次/分钟 打高德，
**更关键的是他完全可以不走本站**，直接拿 key 打 `webapi.amap.com`，那部分我们一行代码都挡不住。这和**高德官方
nginx 样例代理**的暴露面是一样的。控制台侧能收的只有**域名白名单**这一道（2026-10-22 实测：控制台里只有
「Web 服务」那行有【查看配额】，两行「Web 端」只有【设置】/【删除】，所以别指望"设个每日上限"来兜底）。
白名单需要你在控制台确认已配（见第 2 节）。

## 5. 会产生费用的端点

| 端点 | 费用来源 | 上限与护栏（全部在代码里） |
| --- | --- | --- |

| `/api/verify` | 高德 POI + 步行规划 | POI 40/小时、步行 80/小时（`amap.ts:32-33`）+ 6 小时结果缓存 + 30 分钟整条流水线缓存 + **串行节流**（个人 key 只有 2–3 QPS） |
| `/api/agent` | 百炼托管智能体回合 | 40 回合/小时（`bailian.ts:117`）+ **建会话之前**的只读预检（超限连会话都不建）+ 回合 90s 超时 + 同 token/intent/stop 在飞行中去重 |
| `/_AMapService/*`（rewrite 到 `/amap-proxy/*`，同一个 handler） | 高德 JS 服务配额 | 240 次/分钟 + 256 KB + 第 4 节全部白名单 |
| `/api/plan`、`/conditions`、`/propose` | 创建本身读已有事实；修改条件与提案缺边时可能补测 | 所需事实完整且有效时不新增调用；1～6 条缺边可能直接补测，超过 6 条须显式批准；单次补测 ≤9 段、每方案 ≤18 段、与 `/api/verify` **共用**步行小时上限；每方案 40 次写/小时；请求体 ≤8 KB |
| `/api/plan/<id>/explain` | 百炼回合 1 个 | 先过角色凭据与方案有效性（410/401 在花钱之前），再走 `/api/agent` 那套 40 回合/小时上限；同 plan+role+意图在飞行中去重；90s 超时 |
| `GET /api/verify`、`/api/agent`、`/api/discover`、`/api/map-config`、`/api/plan` | 无 | 只回掩码状态、计数与快照位置（`await connection()` 保证读到本实例真实值），不触发外部调用 |

滥用面还做了：请求体 ≤ 8 KB（超出 413）、`stopId`/`token` ≤ 64 字符、`interests` 白名单、未知 `stopId` 在花钱之前就拒绝。

**诚实的边界**：这些计数与缓存都是**进程内**的。单机常驻 = 语义正确；serverless 多实例 = 每个实例各算各的，上限会被实例数放大。部署方式必须和这张表配套，见 [docs/DEPLOYMENT.md](DEPLOYMENT.md)。

## 6. 双人协商：链接是凭据，不是身份证明

| 面 | 做法 | 代码位置 |
| --- | --- | --- |
| 角色链接 | `randomBytes(24)` base64url，planId 与两条令牌同规格；**服务端只存 sha256 哈希**，比对走 `timingSafeEqual` | `src/lib/server/plan-tickets.ts:19-41` |
| 令牌明文出现范围 | 只在 `POST /api/plan` 的那一次响应里以链接形式出现，之后任何响应都不回显（`PUT` 直接 405 说明原因） | `src/app/api/plan/route.ts` 末段 |
| 角色判定 | 双人请求的**角色永远由服务端 `identifyRole(planId, 请求头令牌)` 得出**，请求体里没有可用的 `role` 字段；伪造他人的 planId/role 进不来 | `src/app/api/agent/route.ts:165-184` |
| 作用域键不是凭据 | 会话/回合去重键 `planId|role|版本+行程` 只在服务端内部使用，**从不发给浏览器**；对外解释响应只带它的 12 位截断哈希。夹具测试直接断言「拿作用域键或 planId 冒充角色令牌 → 拒」 | `evidence/negotiation-unit.mjs` 门4c、`evidence/plan-ai.mjs` 19 |
| 单实例写入上限 | 每条方案 40 次写/小时（链接被转发出去也刷不动）、单次求解补测 ≤9 段、每方案累计 ≤18 段、超过 6 段必须显式点「同意新增 N 次实测」 | `plan-store.ts:149-162`、`plan-state.ts:18-21` |
| 幂等 | 条件提交与提案各带一个 `attemptId`，同一次点击重复提交不会二次消耗；两者都带 `expectedRevision`，过期请求先撞版本冲突，**不会先烧掉补测额度**。确认与撤销不发起任何实测（返回里没有缺失段），重复点同一次确认只覆盖时间戳，不会多出版本 | `plan-state.ts:513-538` |
| 410 语义 | 「方案不存在」与「方案已失效」返回同一形状，不给枚举 planId 的反馈；失效原因里如实说明重新核验要烧约 36 次高德请求 | `evidence/plan-guard-probe.mjs` S1/S4 |
| 正式执行门禁 | 未确认／已挂起／核验失败／含未核实站点／开放时间冲突／不再满足双方现行硬条件的版本，一律不执行，也**不会退回**旧的「城市＋类别」单人路线 | `plan-state.ts` `canExecute` / `executionRoute` |
| 单人不能替换双方确认版 | 界面置灰 + 服务端 409 `joint-shorten-refused`，两层都拦 | `PlanActionBar.tsx`、`api/agent/route.ts:173` |

百炼在双人链路里的边界（这是本轮新加的入口，单独说清楚）：

- 唯一入口是「让 AI 解释这次取舍」→ `POST /api/plan/<id>/explain`，**没有自由聊天**。
- 模型读到的是一份服务端拼装的事实块（双方条件、当前版本、判定、矛盾证据、有符号差异、实测数字、
  补测报价），它只能在这些数字里引用；回复里出现的每个「米／分钟」都与服务端实测值逐条对账
  （`src/lib/agent-reply.ts` 的 `auditNumericClaims`），对不上就提示人工确认，合计值也不豁免。
- 它给出的下一步动作只以**键**（`confirm-current` / `alternative-N` / `must-visit-<id>` / `relax-cap-<role>`）
  返回，文案与「需新增 N 次实测」由服务端白名单回填；不在名单里的键进 `rejectedKeys` 显示给用户，
  模型编不出新动作，也**不能替另一方确认**（`relax-cap-<role>` 的提示原文就写着「别人不能代改，AI 也不能代为同意」）。
- 百炼失败时如实显示失败原因，规则求解结果原样保留；服务端不返回任何"看起来像 AI 说的"固定文案。
- 距离、耗时、可行性、硬约束是否满足全部由服务端计算，模型不参与判定。

## 7. 最小快照文件里有什么、没什么

`GET /api/plan` 的 `persist` 字段会如实报告快照位置（相对路径）、大小、写入时间与恢复结果。

- **在文件里**：事实集（地点名、坐标、实测段矩阵、采集时间）、双方条件、版本链与内容哈希、确认与撤销状态、
  角色令牌的 **sha256 哈希**。TTL 锚在**原采集时间**上，不是写盘时间——重启不会把过期方案洗成有效。
- **不在文件里**：任何 API Key、角色令牌明文、百炼 Session ID（会话只活在 `agent.ts` 的进程内表里，
  方案状态不带它）、原始对话内容、本机绝对路径。
  套件用真实文件读取逐条断言这两件事，并检查文件内容不匹配套件里那条密钥形状正则
  （`AMAP_*KEY` / `BAILIAN*KEY` / `sk-…` / `Bearer ` / `jscode` / `securityCode`，大小写都算）。
- **完整性**：写盘走 `tmp + rename` 原子替换，整份带 sha256 校验和；关键状态**先落盘成功再报 `ok`**，
  落盘失败时把已经成功的内存迁移改报 `persist-failed`（HTTP 500），不假装已保存。
- **异常处理**：校验和不匹配 → 整份拒绝恢复并如实报告 `status: "corrupt"`；事实过期 → 方案不恢复，
  执行门禁直接关闭并说明"需要重新核验"。**任何一条路径都不会静默重跑真实 API。**
- **Git**：文件默认在 `<项目>/.data/plan-snapshot.json`，`.gitignore` 已忽略 `.data/`。它属于「这一台机器的
  会话状态」，不是源码。
- 最多持久化 8 条方案（`MAX_PERSISTED_PLANS`），演示场景够用，也避免这个文件无界增长。

## 8. 没有做的事（避免读的人误以为已经做了）

- **没有账号体系** → 限流只有全局小时上限，没有「按访客」维度。公开部署后任何访客都能消耗额度，上限就是为此存在。
- **没有给 `/api/*` 加鉴权**：这是要给评委直接点开的演示项目，加登录就把演示废掉了。兜底手段是上面那张上限表。
- **HTTPS / HSTS 不在本仓库配置**，由部署平台负责。
- **调用日志不持久化** → 无法事后对账；要审计必须引入外部存储，本次没做。
- **链接就是身份，没有"登录"**：拿到 B 那条链接的人，在服务端眼里就是 B——包括点「确认 vN」。
  这是"评委扫一个链接就能体验双人协商"换来的取舍，代价是转发链接等于把这一方的表态权交出去。
  界面在两条链接上方原文写明了这一句，撤销入口（仅 A 可见）会让两条链接当场作废。
- **快照只支持单实例**：`.data/plan-snapshot.json` 是一台机器上的一个文件。多实例部署下每台各写各的，
  一条方案的链接换台机器就找不到（`/api/plan` 的 `pid` 字段就是用来如实暴露这件事的）。
  要真多实例，必须把它换成共享存储——本次没做，也不假装支持。
- **「让 AI 解释这次取舍」的真实百炼回合尚未实测**：链路用夹具与 fetch 桩验过（151 项，零付费），
  但"模型真的返回一段可用解释"需要 1 个真实回合才能确认。实测完成前不宣称这项能力已经跑通。
