## 1. 这是什么

**2026 飞猪 AI 旅行创新大赛参赛项目**，团队「未竟工作室」。公开 MIT 仓库，Demo 在 `travel.peiqirui.com`（线上跑的是旧版本，见 §3.4）。

**产品**：给「带爸妈 / 带长辈出游」的人用的**杭州半日路线工具**。核心不是"AI 帮你规划"，而是：

> **把用户脑子里的限制摊开（可见），并且允许他指哪打哪地改（可改）。**

这句话是用户 2026-11-15 亲自拍板确认的定位（"可以"）。**如果你要改首页或写文案，必须围绕这句，不要写成"智能规划助手"。**

它做的事具体是：
1. 从飞猪拿真实候选地点
2. 用高德逐段实测每段走多少米、多少分钟
3. 在这些**已实测**的路段上，按用户的条件求解出一条路线
4. 算不出来就说清楚是哪条条件卡住的、差多少
5. 改条件**不重新花钱**（复用已测路段）

### 4.4 这台机器的环境坑
| 坑 | 说明 |

### 4.5 事实层是内存态

- 验收脚本必须在**同一个进程**里连着跑完
- 重启后要重新核验（花钱）

### 4.6 「自然风光」类别不稳定（撞过两次）
飞猪这个类别会返回**千岛湖（140km）、径山（31km）**，导致 4 个地点怎么排都超 240 分钟而失败。
**「文创街区」稳定得多，演示请用它。**

### 4.7 付费纪律（用户非常在意）
- **任何真实付费调用前，必须单独提交预算并获得批准**
- 预算要写清上限（高德调用次数 / 飞猪 spawn 次数 / 百炼回合数）
- 跑完如实报「实际花了多少」，超额要主动说
- 不要用 Mock 冒充真实调用

### A 组：方向型（★ 定了才能往下写）

**A1 ★ 产品是什么**
- ① 帮子女排路线的助手　② 多人协商平台　③ **让限制可见、可改的工具**

**A2 ★ 首页形态**
- ① 一句话输入框　② 三个参考选项　③ **选项 + 输入框**
- 用户倾向对话入口（"首页就是一个模型对话入口，准备几个参考的选项"），但担心"创新性差"。
- **建议：③**，并把创新点放在**第二屏的条件卡**（见 A5）。

**A3 ★ 约束该有几条**
- 现在界面上**只有一条**（总步行上限）。但 `HardConstraints` 本来就支持五条：
  `latestEndMinutes` / `maxWalkMeters` / `maxSegmentMeters` / `mustVisit` / `neverAccept`
- **建议：全部露出来**。用户明确说过"凭什么爸妈走不走得动影响整个全局""不该把条件框死"。

**A4 ★ 百炼要不要改 API 直连**
- 现状：**Managed Agent**（`BAILIAN_AGENT_ID`），且 `disableTools: true`
- 两个强队（开口泰、妙游）**都用 API 直连**，按功能分工 3–4 个模型
- **代价**：要重写 `src/lib/server/agent.ts`（约 1000 行），现有 Agent 配置作废
- **建议**：值得。直连能强制 `json_object`、能关思考模式省钱、能精确控制输入

**A5 ★ 换算不了的怎么处理（"膝盖不好" → 多少米）**
- ① 模型猜 + 标「我猜的」　② **不猜，直接问「能走多久」**
- **建议：②**。理由：猜出来的数字最后会显示成「在您定的 2 公里以内」——**但用户从没说过 2 公里，那是我们编的**。
  能算的要算（"半天" → 最晚 13:00），换算不了的必须问。

### B 组：做法型

**B1 飞猪要不要挖深**
- 现在只用 `search-poi`。开口泰用了：预采集快照、每次代码复验 id、推广者分佣；妙游封成受控工具、三本账分开
- **建议**：至少做「预采集快照」+「id 每次复验」（后者我们已有 `auditStopSources`）
- **注意**：用酒店搜索来支撑「中午要坐下吃饭」需要额外付费调用，**必须先报预算**

**B2 写死的参数改不改**
- 现在写死：停留 30 分钟/站、缓冲 20 分钟、240 分钟预算、3–4 站
- **实测：真实那条 191 分钟的路线里，58% 的时长是我们编的**（停留 90 + 缓冲 20），实测步行只占 42%
- **建议**：至少让停留与缓冲可调

**B3 演示数据 419 行**
- ① 删　② 只留在「更多」页当样例
- **建议：②**
